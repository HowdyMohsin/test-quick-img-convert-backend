# Quick IMG Convert — Backend (API)

FastAPI backend for Quick IMG Convert. This repo is the API only (the
frontend and admin panel live in their own repos). Deploy it on Render
with the included `render.yaml` blueprint.

## Deploy on Render (free, test only)

1. Render dashboard → **New → Blueprint** → connect this repo.
2. Render creates two things: the `quick-img-convert-api` web service and
   the `quick-img-convert-db` PostgreSQL database. When it asks, fill in:
   - **DATABASE_URL** — open the new database in Render, copy its
     **External Database URL**, and change ONLY the scheme at the start:
     `postgres://` → `postgresql+asyncpg://`
     (the API uses SQLAlchemy's async engine, which needs the asyncpg scheme)
   - **ADMIN_EMAIL** — your admin email (e.g. your own email address)
   - **ADMIN_PASSWORD** — a strong password for the first admin account
   - `SECRET_KEY` and `APP_SECRET` are generated by Render automatically.
3. Deploy. The first start runs the database migrations and creates the
   first admin from `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
4. Your API URL is `https://quick-img-convert-api.onrender.com`.
   Check `https://quick-img-convert-api.onrender.com/healthz` — it should
   return `{"status": "ok", ...}`.
5. Point the frontend at it: in Vercel, set the frontend project's
   `NEXT_PUBLIC_API_URL` and `API_INTERNAL_URL` to the API URL above,
   then **Redeploy** the frontend (these values are baked in at build time).

## What works on Render free — and what does not

Works: accounts, login, plans, admin panel data, settings, ads config —
everything the API serves from the database.

Does NOT work here: **conversions**. The conversion worker is a separate
process and Render's free tier has no free background workers, so jobs will
queue in the database until a worker runs somewhere (the Oracle VPS or the
owner's PC with Docker). This is a Render free-tier limit, not a code bug.

Free-tier limits to know: the web service sleeps after ~15 minutes idle
(first request after sleep is slow), and the free database expires after
30 days. For the real launch, the backend belongs on the Oracle VPS.

## Lightweight tuning (512 MB free instance)

The API is tuned to run lean on the free tier, and the same code runs
unchanged on Docker/PC/Oracle:

- Single uvicorn worker, `--limit-concurrency 40`, 5 s keep-alive.
- Small database pools: async engine 5 + 2, sync pipeline store 3 + 2
  (one API holds at most 12 connections), with pre-ping and 5-minute
  recycle — safe for the small free PostgreSQL.
- `pip install --no-cache-dir`, so the build keeps no wheel cache.
- The first-boot pair health check is skipped on Render
  (`QIC_STARTUP_HEALTH_CHECK=0`); it converts bundled samples in a
  background thread at boot, which the 512 MB instance does not need.
  The admin formats page shows no health data until a check is run.
- Uploads still stream to disk in 1 MB chunks and conversion work stays
  off the event loop; only the API runs here (no worker on free tier),
  so conversions queue in the database.

## Local run

```bash
cp .env.example .env   # fill in real values
pip install -r requirements.txt
./entrypoint.sh uvicorn app.main:app --host 0.0.0.0 --port 8000
```

`.env.example` lists every variable the API reads. Never commit a real
`.env` — it is gitignored.
